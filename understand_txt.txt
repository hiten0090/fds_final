1. PROJECT OVERVIEW & EXECUTIVE SUMMARY
================================================================================
FireGuard Pro is an enterprise-grade IoT Fire Hazard Monitoring, Digital Twin 
Facility Dashboard, and Emergency Operations Command System. It is designed for 
factories, server rooms, commercial buildings, and smart facilities.

Key Highlights:
1. Zero-Latency Local Edge Fail-Safe:
   The physical microcontroller (ESP32-S3) triggers the hardware alarm siren relay
   locally (0ms latency), independent of Wi-Fi or cloud status.
2. Cloud Real-Time Telemetry:
   Telemetry streams every 1.0s via HTTPS REST POST to Supabase Cloud Database.
   The frontend connects via WebSockets (Supabase Realtime) for sub-second updates.
3. Smart Hardware Offline Detection:
   When the ESP32 is powered off or unplugged (>15 seconds without packets), the 
   dashboard gracefully displays "Hardware Offline (Standby)", clears old sensor 
   readings to "--.-", prevents stale records from triggering false alarms, and 
   turns off fake wave animations.
4. Emergency Protocol:
   Upon confirmed fire (Multi-sensor AND logic OR Manual Override), the system triggers:
   - Fullscreen Red Emergency Evacuation Modal
   - Web Audio API dual-tone synthesized evacuation siren
   - Priority ESP32-CAM video surveillance stream
   - Incident logging and 1-Click WhatsApp / SMS emergency dispatch

3. SENSOR CALIBRATION, BASELINES & DETECTION THRESHOLDS
================================================================================
A. Calibration Period (First 15 Seconds from Boot):
   - During the first 15 seconds (`CALIBRATION_DURATION = 15000`), the ESP32
     samples ambient room conditions to calculate baseline averages:
     * `tempBaseline`: Average room temperature (default fallback: 25.0 °C)
     * `gasBaseline`: Average room air ADC (default fallback: 350 ADC)
   - Baseline ready flag is set (`baselineReady = true`).

B. Sensor Alert Thresholds:
   -----------------------------------------------------------------------------
   Sensor       Alert Condition                               Card Display
   -----------------------------------------------------------------------------
   Temperature  Temperature >= 20.0 °C  OR                    "Limit: 20°C
   (DHT22)      Temperature >= (tempBaseline + 2.0 °C)         (Baseline +2.0°C)"
                -> Sets `temperature_alert = true`

   Smoke / Gas  gasValue >= 800 ADC  OR                       "Trigger: 800 ADC
   (MQ-2)       gasValue >= (gasBaseline + 150 ADC)            (Baseline +150)"
                -> Sets `gas_alert = true`
                * If ADC < 35, sensor is marked disconnected (`gas_state = false`)

   Flame Sensor digitalRead(GPIO 6) == LOW (0V)               "Active: LOW (0V)"
   (Optical IR) -> Sets `flame_alert = true`
                -> Sets `flame_state = 1` (CRITICAL)
                * When HIGH (3.3V) -> `flame_state = 0` (CLEAR / SAFE)
   -----------------------------------------------------------------------------

C. Multi-Sensor Emergency Siren (Buzzer) Activation Rule:
   In ESP32 firmware:
   ```cpp
   if (temperatureAlert && gasAlert && flameAlert) {
       buzzerState = true;
       digitalWrite(BUZZER_PIN, HIGH);
   } else {
       buzzerState = false;
       digitalWrite(BUZZER_PIN, LOW);
   }
   ```
   * All 3 hazards must be present simultaneously to trip the automated siren:
     (Temperature Spike + Smoke Spike + Optical Flame Detected).
   * This strictly prevents false alarms from isolated sunlight or brief vapor.

6. SMART OFFLINE & DEMO DATA POLICIES
================================================================================
A. Honest Offline Mode:
   - If no packet arrives from ESP32 for >15 seconds (`diffSeconds > 15`):
     * `isDataStale` becomes `true`.
     * Temperature reading shows: `--.- °C`
     * Smoke reading shows: `-- PPM`
     * Flame reading shows: `OFFLINE ( -- )`
     * Hardware pills display: `Hardware Offline` (neutral grey/amber dot).
     * Status rows display: `Device Offline / Standby` (no false `CRITICAL` alarms).
     * Header badge displays: `HARDWARE OFFLINE (STANDBY)`.
     * Old/historical rows in Supabase NEVER trigger emergency sirens when offline.

B. No Fake Sine-Wave Oscillations:
   - When the hardware is offline, all graphs flatline at neutral 0.
   - Fake `Math.sin()` / `Math.cos()` wave generators were eliminated.
   - When live, graphs track real, unfiltered hardware values directly.

C. When ESP32 Powers ON:
   - In <1 second, incoming packet sets `isDataStale = false`.
   - Cards instantly turn to green `Hardware Connected`.
   - Real telemetry streams live into charts and cards.
   - If fire is present (`flame_state == 1`), Flame Card turns `🔥 CRITICAL (1)` 
     with a pulsing red aura.
